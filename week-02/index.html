03 개념에 이름 붙이기

정형 데이터는 정해진 항목과 구조에 맞추어 기록합니다. 학교마다 코드·학교명·주소를 같은 컬럼에 넣은 표가 이에 해당합니다.

비정형 데이터는 내용을 고정된 표의 항목만으로 곧바로 나누기 어렵습니다. 자유롭게 쓴 설명이나 사진·소리처럼 구조를 따로 정해야 하는 자료를 생각할 수 있습니다.

한 표 안에도 자유로운 메뉴 문장이 들어갈 수 있습니다. 표라는 전체 구조와, 한 칸에 담긴 내용의 형태를 함께 살펴야 합니다.

속성은 관찰 대상에 대해 기록한 항목입니다. 자료형은 그 값을 프로그램이 어떤 종류로 다룰지 정합니다. 숫자 모양이라는 이유만으로 모두 계산 대상으로 삼지는 않습니다.

학교·급식 표에서 살펴볼 컬럼의 역할
속성역할다룰 자료형
표준학교코드학교 식별문자열 · 크기나 평균을 해석하지 않음
급식일자언제 제공했는지 기록날짜 · 문자열로 받아도 역할은 날짜
식사종류조식·중식·석식 구분범주
급식인원사람 수 기록수량 · 계산 전 실제 표현과 단위 확인
요리명메뉴 내용 기록텍스트

프로그램이 자동으로 읽은 자료형과 분석에 필요한 역할이 일치하는지는 실제 값과 함께 확인합니다.

03 개념에 이름 붙이기

NEIS는 인증키가 없는 요청을 체험용으로 처리하여 최대 5건만 제공합니다. 요청 크기를 늘려도 이 제한이 바뀌지는 않습니다. 검색 조건에 맞는 자료가 적으면 5건보다 적게 올 수도 있습니다.

API는 프로그램끼리 정보를 요청하고 응답받기 위해 정한 약속입니다. 주소와 조건을 보내면 서버가 정해진 형식으로 답합니다. 인증키는 요청자를 식별하고 이용 범위를 관리하는 데 사용합니다.

이 수업에서 전체 수집은 교사의 키로 합니다. 학생은 키를 발급받지 않습니다. NEIS 공식 명세(새 탭)에서 제한을 확인합니다.

요청 조건
교육청·학교 종류·학교명처럼 원하는 자료의 범위를 정합니다.
페이지
자료를 일정 크기로 나누어 받습니다. pIndex는 페이지 번호, pSize는 요청할 행 수입니다. 무인증은 첫 페이지·최대 5건으로 제한되므로 페이지를 늘려 전체 수집을 시도하지 않습니다.
JSON
이름과 값, 목록과 계층으로 내용을 표현합니다. 표와 다른 계층 구조를 가진 반정형 표현이며, row 목록을 골라 데이터프레임으로 바꿀 수 있습니다.

수집 방법에는 직접 관찰·설문, 공개 파일 다운로드, API 요청 등이 있습니다. 같은 정보를 반복해서 조건별로 가져올 때 API가 어떤 도움을 주는지 생각해 봅시다.

API 셀 2 · 그대로 실행할 요청 함수

응답의 row만 표로 바꿉니다. 오류가 나면 자료로 해석하지 않고 멈춥니다.

def school_table(params):
    try:
        response = requests.get("https://open.neis.go.kr/hub/schoolInfo",
                                params=params, timeout=30)
        if response.status_code != 200:
            raise RuntimeError(f"HTTP 오류: {response.status_code}")
        payload = response.json()
    except (requests.RequestException, ValueError):
        raise RuntimeError("연결 또는 JSON 응답을 확인하세요.") from None
    blocks = payload.get("schoolInfo", [])
    rows = next((block["row"] for block in blocks if "row" in block), [])
    if not rows:
        raise RuntimeError("학교 자료가 없습니다. 요청 조건·인증키를 확인하세요.")
    return pd.DataFrame(rows)

API 셀 3 · 브라우저와 같은 조건으로 요청

params = {
    "Type": "json", "ATPT_OFCDC_SC_CODE": "B10",
    "SCHUL_KND_SC_NM": "고등학교",
    "pIndex": 1, "pSize": 100,
}
time.sleep(1)
schools_preview = school_table(params)
columns = ["SD_SCHUL_CODE", "SCHUL_NM", "SCHUL_KND_SC_NM", "ORG_RDNMA"]
print("요청한 크기:", params["pSize"])
print("실제로 받은 행 수:", len(schools_preview))
display(schools_preview[columns])

기대되는 관찰은 요청 100건, 반환 최대 5건입니다. 여기서 받은 수가 서울의 전체 학교 수는 아닙니다. 이 활동은 CSV를 생성하지 않습니다.

API 셀 4 · 요청 크기를 바꾸면?

changed = {**params, "pSize": 20}
time.sleep(1)
changed_preview = school_table(changed)
print("요청한 크기:", changed["pSize"])
print("실제로 받은 행 수:", len(changed_preview))
display(changed_preview[columns])

반환 수가 달라졌나요? 요청 크기를 바꾸어도 최대 5건인 이유를 기록합니다. 다음 확장 활동에서는 학교 이름으로 직접 검색해 봅니다.

확장 활동 · “내가 아는 학교도 정말 나올까?”

API 셀 1~3을 실행한 뒤 아래 셀을 실행합니다. school_name의 학교 이름만 바꾸어 친구가 다니는 학교나 예전에 다니던 학교를 찾아보세요. 지역과 학교급은 제한하지 않습니다.

인증키 없이 최대 5건까지만 받아도 학교 조회가 된다는 것을 확인하기에는 충분합니다. 학교명·학교급·주소를 보고 찾던 학교인지 확인하세요. 동명이교가 있거나 결과가 없으면 학교의 정식 이름으로 다시 검색합니다.

유효한 키와 충분한 검색 결과가 있으면 무인증의 5건 제한과 다른 결과를 확인할 수 있습니다. head()는 받은 표의 처음 다섯 행만 보여 주므로 전체 수는 출력한 행 수로 확인합니다. 노트북을 공유하기 전 키를 자리표시자로 되돌리고 키가 든 변수·요청 주소를 출력하지 않습니다.

03 개념에 이름 붙이기

학교 표는 한 행에 한 학교를 기록합니다. 급식 표는 한 학교의 한 날짜·한 식사를 한 행으로 기록합니다. 같은 날짜의 조식·중식·석식은 서로 다른 행입니다.

학교명만 읽는 데서 더 나아가 교육청코드와 표준학교코드를 함께 확인합니다. 두 표에서 같은 학교를 찾는 기준이 되며, 3주차 데이터 통합에서 사용합니다.

행 수는 식사 기록의 수이고, 고유 급식일 수는 중복 없이 센 날짜 수입니다. 같은 날 세 식사를 운영해도 고유 급식일은 1일입니다.

인원 차이는 이용 대상의 차이를 시사한다

관찰: 명덕고의 해당 날짜 조식·석식 인원이 중식보다 훨씬 적습니다. 명덕고에는 방학 중 급식 기록도 있습니다.

가설: 조식·석식이 기숙사생처럼 학교에 머무는 일부 학생을 대상으로 할 수 있습니다.

이 숫자에는 이용 학생의 신분이 적혀 있지 않습니다. 가설을 확인하려면 학교의 급식·기숙사 운영 안내 같은 추가 근거가 필요합니다. 다른 설명도 한 가지 제안해 보세요.
