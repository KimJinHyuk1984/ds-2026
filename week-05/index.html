mask = long["메뉴원문"].str.contains(

설명 중 무엇을 잃었나요? 시리얼 종류·깍둑 형태·갈치 설명·조식 구분을 지운 결과가 원래 메뉴와 같은 의미인지 기록합니다. long은 그대로 두고 사본에서만 실험합니다.

첫 숫자 괄호만 추출하면 무엇을 가져왔는지, 모든 숫자 괄호를 지우면 무엇을 잃는지 먼저 설명합니다.

실패 기록 후 적용할 규칙

현재 자료의 알레르기 번호 표시는 메뉴 끝의 숫자·점 괄호에 있습니다. 학교급식 번호 목록의 1~19 범위도 확인합니다. (24.03)·(23.06)·(100)은 앞쪽 메뉴 정보로 남깁니다.

다음 코드는 끝의 후보 하나를 확인하고 그 부분만 떼어 냅니다. 설명 괄호·별표·내부 공백·다른 문장부호는 보존하고, 양 끝 공백만 정리합니다. 이것이 이번 실습의 정규화 범위입니다.

import re

tail_pattern = re.compile(r"\(([0-9]+(?:\.[0-9]+)*)\)\s*$")
allowed_codes = set(range(1, 20))

$로 끝을 제한했습니다. 이 패턴도 문자의 뜻을 판별하지는 못합니다. 설명용 숫자가 1~19 범위로 끝에 놓이는 자료에서는 원문 확인이 더 필요합니다.

def parse_menu(text):
    text = text.strip()
    match = tail_pattern.search(text)
    if match is None:
        return text, ""
    numbers = [int(value) for value in match[1].split(".")]
    if not all(value in allowed_codes for value in numbers):
        raise ValueError("끝의 번호 범위 확인: " + text)
    codes = ",".join(str(value) for value in dict.fromkeys(numbers))
    return text[:match.start()].strip(), codes

번호는 쉼표로 연결한 문자열로 만들며 같은 번호의 중복만 첫 등장 순서로 정리합니다. 번호 표시가 없으면 빈 문자열로 남깁니다. 표시 없음이 실제 유발 성분 없음이라는 뜻은 아닙니다.

pairs = long["메뉴원문"].map(parse_menu)
parsed = long[meta].copy()
parsed[["메뉴명", "알레르기번호"]] = pd.DataFrame(pairs.tolist(), index=long.index)
print(parsed.shape, "번호 미표기:", parsed["알레르기번호"].eq("").sum())
review = pd.concat([long["메뉴원문"], parsed[["메뉴명", "알레르기번호"]]], axis=1)
display(review.loc[mask].drop_duplicates().head(12))
display(review.loc[long["메뉴원문"].str.count(numeric_pattern).gt(1)].drop_duplicates())

예상 결과는 (10274, 8), 번호 미표기 1,629개입니다. 앞서 잃었던 메뉴 설명과 (24.03)·(100)이 살아 있고, 끝의 알레르기 번호만 분리되었는지 직접 대조합니다.

03 개념에 이름 붙이기

파생변수는 기존 자료를 질문에 맞게 계산해 만든 새 속성입니다. 한 급식은 학교코드·급식일자·식사종류의 조합으로 구분합니다. 날짜만 묶으면 여러 학교와 식사가 섞입니다.

메뉴 개수는 그 급식의 메뉴 행 수입니다. 알레르기 유발 표시가 있는 메뉴 비율은 번호가 표기된 메뉴 수 ÷ 전체 메뉴 수 × 100입니다.

번호가 5개인 메뉴도 ‘번호가 표기된 메뉴’ 1개로 셉니다. 미표기 메뉴에 유발 성분이 없다고 단정하지 않으며, 이 변수는 원문의 표시 상태를 요약합니다.

분모를 적어야 비교가 된다

빈도는 등장 횟수입니다. 학교별 메뉴 비중은 해당 메뉴 행 수를 그 학교 전체 메뉴 행 수로 나눈 비율입니다. 전체 합계만 비교하면 기록량이 큰 학교가 과대 대표됩니다.

데이터 편향은 수집·구성·처리 과정에서 일부 대상이 더 많이 반영되거나 비교 조건이 달라지는 문제입니다. 비율로 크기 차이를 줄여도 식사 종류·기간·표기 방식 차이는 남습니다.

급식인원은 메뉴마다 반복된 메타데이터입니다. 메뉴 행에서 합산하면 같은 사람 수를 여러 번 더하므로 합산하지 않습니다.

04 Python으로 재현

work = parsed.assign(번호표기=parsed["알레르기번호"].ne(""))
meal_stats = work.groupby(["학교명"] + keys, as_index=False).agg(
    메뉴개수=("메뉴명", "size"), 표기메뉴수=("번호표기", "sum"),
    급식인원=("급식인원", "first"))
meal_stats["알레르기표기비율(%)"] = (
    meal_stats["표기메뉴수"] / meal_stats["메뉴개수"] * 100)
print("급식별 요약 행:", len(meal_stats))
display(meal_stats.head())

1,504급식으로 돌아오는지 확인합니다. 급식인원은 반복값 중 첫 값을 가져오며 합산하지 않습니다. 날짜·학교 조건으로 같은 급식을 골라 원문에서 직접 센 메뉴 수와 대조합니다.

학교를 세현고등학교로 바꾸어 상위 메뉴를 비교합니다. 처음에는 전체 식사를 사용하고, 이후 meal_kind를 중식으로 바꿔 셀 12 이후를 다시 실행합니다. 현재 표기 그대로의 이름 기준이므로 별칭·별표 차이도 다른 이름으로 셉니다.

menu = "배추김치"
denominator = scope.groupby("학교명").size()
frequency = scope.loc[scope["메뉴명"].eq(menu)].groupby("학교명").size()
comparison = pd.DataFrame({"전체메뉴수": denominator,
    "빈도": frequency.reindex(denominator.index, fill_value=0)})
comparison["메뉴비중(%)"] = comparison["빈도"] / comparison["전체메뉴수"] * 100
display(comparison.round(2))

menu를 빈도표의 다른 실제 메뉴명으로 바꿉니다. 여기의 0은 결측 대체가 아니라 해당 학교의 선택 범위에서 그 이름의 메뉴가 0번 등장했다는 집계값입니다.

학교별 전체 메뉴를 분모로 삼았습니다. ‘학교가 그 메뉴를 제공한 급식의 비율’이나 ‘학생의 선호도’와 같지 않습니다.
