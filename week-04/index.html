빈 값은 어디에 있을까?

01 질문 제기

“353일이 빠짐없이 있는데, 표 안에도 빠진 정보가 없을까?”

1주차에서 보았던 강수량 빈칸을 다시 찾습니다. 먼저 개수를 예상하고, 빈칸이 있는 컬럼과 날짜를 기록합니다. 아직 값을 바꾸지 않습니다.

02 Orange3에서 결과 확인

  1. File → Data Table로 bike-daily.csv의 353행을 확인합니다. 강수량은 Numeric으로 읽습니다.
  2. 같은 File에서 Impute → 별도의 Data Table로 연결합니다. Impute의 기본값은 평균 대체이므로 먼저 전체 방법을 Don't Impute로 바꾸고, 강수량에 별도 대체 설정이 남아 있지 않은지 확인한 뒤 적용합니다.
  3. 두 Data Table에서 강수량의 빈칸 표시를 비교합니다. 이 차시에는 처리 전 표와 같은 상태를 유지합니다.
  4. File에서 Select Rows도 연결해 강수량의 값이 없는 조건을 선택합니다. Matching Data를 Data Table로 보내 해당 날짜만 셉니다.

확인할 결과는 강수량 빈 값 200개입니다. Impute에서 방법을 선택할 수 있다는 사실과 실제로 적용했다는 사실을 구분합니다.

03 개념에 이름 붙이기

결측치는 표에 값이 비어 있거나 관측값이 기록되지 않은 상태입니다. pandas에서는 숫자 컬럼의 빈 값을 보통 NaN으로 표시합니다.

0은 기록된 수치이고 빈칸은 기록 방식의 문제일 수도 있습니다. 화면만 보고 두 상태가 같은 의미인지 판단할 수는 없습니다.

날짜 행 자체가 없는 경우와, 날짜는 있지만 특정 컬럼만 빈 경우도 구별합니다. 지금 표는 날짜 누락이 없으므로 강수량 셀의 상태를 조사합니다.

04 Python으로 재현

import pandas as pd
from IPython.display import display

base = "https://kimjinhyuk1984.github.io/ds-2026/data/"
bike = pd.read_csv(base + "weather-bike/bike-daily.csv", encoding="utf-8-sig")
meals = pd.read_csv(base + "neis/meals.csv", encoding="utf-8-sig",
                    dtype={"표준학교코드": str, "식사코드": str})
print("기상·따릉이 / 급식:", bike.shape, meals.shape)

(353, 8), (1504, 12)를 확인합니다. 업로드가 필요한 환경에서는 내려받은 파일을 Colab 왼쪽 파일 영역에 올리고 URL 대신 해당 경로를 넣을 수 있습니다.

display(bike.isna().sum().rename("결측 개수"))
column = "강수량"
missing_mask = bike[column].isna()
print("선택 컬럼의 빈 값:", missing_mask.sum())
display(bike.loc[missing_mask, ["날짜", column, "대여건수"]].head())
print("급식 표 전체 빈 값:", meals.isna().sum().sum())

column을 평균기온·대여건수로 바꿔 확인합니다. 급식 원본에는 모든 컬럼을 합쳐도 빈 값이 0개입니다. 다음 차시의 강수량 비교 전에는 column = "강수량"으로 돌려놓습니다.

이번 주 2차시 · 11차시

빈칸의 의미를 확인하고 처리하기

01 질문 제기

“200개의 빈칸을 평균으로 채우면 원래 날씨에 가까워질까?”

교사가 원본의 기록 방식을 확인했습니다. 이 자료의 강수량 공백은 비가 오지 않은 날을 뜻합니다. 일부 무강수일은 숫자 0으로, 일부는 공백으로 기록되어 있습니다.

이제 ‘알 수 없는 강수량’이 아니라 ‘무강수를 다르게 기록한 경우’라는 맥락을 알고 세 가지 처리를 비교합니다. 이 설명을 다른 데이터의 모든 빈칸에 적용하지 않습니다.

02 Orange3에서 결과 확인

  1. File 원본에서 Impute 3개를 각각 연결합니다. 처리된 출력을 다음 Impute에 이어 붙이지 않습니다.
  2. 각 Impute에서 전체 기본값은 Don't Impute로 두고, 강수량만 선택해 방법을 바꿉니다.
  3. A는 Average/Most-frequent, B는 Remove instances with unknown values, C는 Fixed values의 수치 0을 지정합니다.
  4. 각 출력을 별도 Data Table에 연결해 행 수와 10차시에 찾았던 같은 날짜의 강수량을 비교합니다. C는 수업에서 선택할 처리 결과입니다.

A와 C는 353행, B는 153행입니다. A에서는 비가 없던 날에 약 8.1mm가 들어가고, B에서는 그 날짜가 사라지며, C에서는 날짜를 유지하고 0mm로 표시됩니다.

03 개념에 이름 붙이기

대체는 빈칸에 값을 넣는 처리입니다. 평균 대체는 관측된 값의 평균을 넣지만, 여기서는 기록 맥락과 맞지 않습니다.

행 삭제는 해당 날짜의 기온·대여건수 등 다른 관측까지 함께 잃게 합니다. 지금은 유효한 무강수일 200일을 버리므로 비가 있는 날 쪽으로 분석 자료가 치우칩니다.

이 자료에서는 출처 확인을 근거로 강수량 빈칸만 0으로 바꿉니다. 3주차 Merge에서 상대 학교 기록이 없어 생긴 빈칸까지 ‘급식인원 0명’으로 채우는 근거가 되지는 않습니다.

04 Python으로 재현

rain = bike["강수량"]
print("공백:", rain.isna().sum())
print("명시적인 0:", rain.eq(0).sum())
print("관측값 수:", rain.notna().sum())
print(f"관측값만의 평균: {rain.mean():.1f} mm")

공백 200개, 명시적인 0은 51개, 관측값은 153개입니다. pandas의 평균 계산은 빈 값을 제외합니다. 따라서 약 8.1mm는 353일 전체의 올바른 평균이 아닙니다.

mean_filled = bike.copy()
mean_filled["강수량"] = mean_filled["강수량"].fillna(rain.mean())
rows_dropped = bike.dropna(subset=["강수량"]).copy()
bike_clean = bike.copy()
bike_clean["강수량"] = bike_clean["강수량"].fillna(0)

variants = {"원본": bike, "평균 대체": mean_filled,
            "행 삭제": rows_dropped, "0 대체": bike_clean}

평균 대체와 삭제는 영향을 확인하기 위한 비교용입니다. 수업에서 선택한 결과는 bike_clean이며 원본 변수 bike는 바꾸지 않습니다.

summary = pd.DataFrame({
    name: {"행 수": len(frame), "강수량 결측": frame["강수량"].isna().sum(),
           "강수량 평균(mm)": frame["강수량"].mean()}
    for name, frame in variants.items()

day를 자신이 찾은 다른 날짜로 바꿉니다. 같은 날짜의 빈칸·약 8.1·행 부재·0을 각각 확인합니다. 코드의 평균은 반올림하지 않고 계산하며 표에서 비교할 때만 소수 첫째 자리까지 읽습니다.

눈에 띄는 값을 지우기 전에

01 질문 제기

“대여건수 14,293건과 194,244건, 급식인원 60명과 1,005명은 너무 다르니 지워야 할까?”

값이 범위의 끝에 있다는 관찰과 기록이 잘못됐다는 판단을 구분합니다. 날짜·날씨·식사 종류를 함께 확인하기 전에는 어떤 행도 제외하지 않습니다.

02 Orange3에서 결과 확인

  1. 따릉이 원본 File → Box Plot을 연결하고 대여건수를 선택합니다. Data Table에서는 대여건수를 정렬해 양 끝 날짜를 확인합니다.
  2. 별도 File에서 meals.csv를 엽니다. 급식인원은 Numeric, 식사종류는 Categorical로 지정합니다.
  3. Select Rows로 명덕고등학교만 고른 뒤 Box Plot에서 급식인원을 선택하고 식사종류로 하위 집단을 나눕니다.
  4. Data Table에서 2024-03-05를 찾아 조식 60명·중식 1,005명·석식 55명을 비교합니다. 2주차에 본 3월 4일과 다른 날짜입니다.

한 학교의 모든 식사를 한 집단으로 볼 때와 식사별로 나눠 볼 때, 작은 인원을 해석하는 근거가 어떻게 달라지는지 기록합니다.

탐지 결과는 검토 목록으로 사용하기

  1. 따릉이 원본 File → Select Columns → Outliers를 연결합니다. Select Columns에서는 Features에 대여건수만 두고 날짜·날씨 등 나머지 컬럼은 Meta로 옮깁니다. Target은 비웁니다.
  2. Outliers에서 Local Outlier Factor를 선택합니다. Neighbors 20, Metric Euclidean, Contamination 10%로 맞춰 적용합니다.
  3. Data 출력을 Data Table로 보내 전체 353행과 추가된 Outlier 표시를 확인합니다. Outliers 출력은 별도 Data Table에서 후보 날짜를 살펴보는 데만 씁니다.
  4. Contamination을 5%로 바꾸어 후보 수와 날짜가 어떻게 달라지는지 기록합니다. 입력한 비율은 실제 오류 비율을 확인한 값이 아닙니다.

Outliers 위젯의 LOF와 뒤의 Python IQR은 다른 탐지 기준입니다. 후보 수가 같을 필요는 없습니다. Inliers만 저장하거나 후보를 자동 삭제하지 않습니다.

03 개념에 이름 붙이기

극단값은 관측 범위의 작은 끝이나 큰 끝에 있는 값입니다. 이상치 후보는 정한 비교 집단과 탐지 기준에서 두드러지는 관측입니다. 어느 쪽도 오류라는 판정과 같지 않습니다.

IQR(사분위 범위)은 가운데 절반의 퍼짐을 나타내는 Q3 − Q1입니다. 이번 Python 실습에서는 Q1 − 1.5×IQR보다 작거나 Q3 + 1.5×IQR보다 큰 값을 후보로 표시합니다.

LOF는 주변 관측과의 밀도를 비교합니다. 방법이나 설정, 비교 집단에 따라 후보가 달라지므로 “어떤 기준으로 찾았는가”를 함께 적어야 합니다.

04 Python으로 재현

rentals = bike["대여건수"]
q1, q3 = rentals.quantile([0.25, 0.75])
iqr = q3 - q1
k = 1.5
lower, upper = q1 - k * iqr, q3 + k * iqr
candidate = rentals.lt(lower) | rentals.gt(upper)
print("Q1 / Q3 / IQR:", q1, q3, iqr)
print("하한 / 상한 / 후보 수:", lower, upper, candidate.sum())
display(bike.loc[candidate, ["날짜", "평균기온", "강수량", "대여건수"]])

Q1=78,186, Q3=164,906, IQR=86,720입니다. 경계는 −51,894와 294,986이고 후보는 0건입니다. 코드 오류가 아니라 이 기준으로 탐지되지 않았다는 결과입니다.

columns = ["날짜", "요일", "공휴일여부", "평균기온", "강수량", "대여건수"]
extreme_rows = [bike["대여건수"].idxmin(), bike["대여건수"].idxmax()]
display(bike.loc[extreme_rows, columns])

최소 14,293건은 2024-05-05로 강수량 48.3mm, 평균기온 17.8°C, 공휴일여부 1입니다. 폭설·한파 때문이라고 설명할 수 있는 관측이 아닙니다. 비와 휴일이 영향을 주었는지는 추가 비교가 필요합니다.

최대 194,244건은 2024-06-04입니다. 단지 최댓값이라는 이유로 제거하지 않습니다. 두 행 모두 보존합니다.
