많은 기록을, 질문에 맞는 표로

01 질문 제기

“서울의 하루 대여량을 보려면 원본 38,286,211행이 모두 필요할까?”

12개월 따릉이 시간대별 원본은 38,286,211행이었습니다. 교사가 날짜별로 대여건수를 합산하고 기상과 연결해, 수업에서는 353행을 사용합니다.

38,286,211은 원본의 행 수입니다. 대여 횟수의 합계와 구별합니다. 최종 기간은 원본 제공 범위에 맞춰 2024-03-01~2025-02-16입니다.

02 Orange3에서 결과 확인

  1. File에서 bike-daily.csv를 열고 Data Table에 연결해 353행 × 8컬럼을 확인합니다.
  2. 날짜·대여건수·평균기온을 찾습니다. 한 행이 어떤 대상을 뜻하는지 설명합니다.
  3. “어느 날 대여가 많았나?”와 “어느 대여소의 밤 10시 대여가 많았나?” 중 이 표로 답할 수 있는 질문을 고릅니다.

대여소와 시간대 컬럼은 일별 전체 합계에 없습니다. 같은 합계라도 장소·시간대별 모습은 서로 다를 수 있습니다.

03 개념에 이름 붙이기

빅데이터는 규모, 쌓이는 속도, 형태의 다양성 때문에 저장·처리·분석 방법을 함께 설계해야 하는 데이터를 가리킵니다. 몇 행 이상이라는 한 숫자로만 정하지 않습니다.

집계는 질문에 맞는 단위로 묶어 합계 같은 요약값을 만드는 일입니다. 일별 서울 전체 대여량이 질문이라면 작은 표로 빠르게 비교할 수 있습니다.

집계한 합계만으로 대여소·시간대별 원래 값을 되살릴 수는 없습니다. 처리 부담을 줄이는 대신 잃는 세부 정보가 있습니다.

저장하고 관리하는 곳, 분석에 쓰는 묶음

데이터베이스는 자료를 정해진 구조와 관계에 따라 저장하고 관리하는 체계입니다. DBMS는 자료를 검색·추가·수정하고 여러 사용자의 접근과 일관성을 관리하는 소프트웨어입니다.

데이터셋은 특정 질문이나 작업을 위해 모은 자료의 묶음입니다. 지금의 CSV 3개는 수업용 데이터셋이며, CSV 파일 자체가 데이터베이스 관리 시스템인 것은 아닙니다.

학교 표는 한 학교에 한 행, 급식 표는 학교·날짜·식사마다 한 행입니다. 학교의 주소를 한 곳에서 관리하고 학교코드로 연결하면 같은 정보를 매 식사마다 따로 고칠 필요가 줄어듭니다.

이번 주 2차시 · 8차시

Concatenate · 같은 구조를 세로로

01 질문 제기

“네 학교의 급식 표를 붙이면 행과 열 중 무엇이 늘어날까?”

meals.csv는 이미 네 학교가 합쳐진 표입니다. 학교별로 나눈 뒤 다시 붙여서, 전체를 정확히 되돌릴 수 있는지 확인합니다.

명덕고에만 있는 조식과 세현고에 없는 석식은 표에 어떤 모습으로 남을까요?

02 Orange3에서 결과 확인

  1. File에서 meals.csv를 열고 Select Rows 네 개로 나눠 연결합니다.
  2. 학교명 조건을 각각 동양·명덕·영일·세현고등학교로 정합니다. 다른 조건은 넣지 않습니다.
  3. 각 Matching Data를 Data Table로 확인합니다. 순서대로 302·743·300·159행입니다.

Select Rows의 ‘Remove unused values and constant features’와 ‘Remove unused classes’를 끕니다. 원래 12컬럼과 자료형을 유지하고, 조건에 맞는 행만 고릅니다.

학교별 네 출력을 하나의 Concatenate로

  1. 네 Matching Data 출력을 Concatenate의 Additional Data 입력에 모두 연결합니다. Primary Data 입력은 비워 둡니다.
  2. 모든 입력의 컬럼을 사용하는 옵션을 선택하고 출처 ID 추가는 끕니다. Data Table로 출력을 확인합니다.
  3. 결과는 1,504행 × 12컬럼입니다. File의 전체 표와 학교별 행 수가 일치하는지 확인합니다.

학교명과 식사종류를 함께 봅니다. 명덕고에서 조식을 찾을 수 있지만 세현고에서 석식인 행은 찾을 수 없습니다.

03 개념에 이름 붙이기

Concatenate는 같은 의미의 컬럼을 맞추어 행을 아래로 이어 붙이는 결합입니다. 이번에는 302+743+300+159=1,504행이 되고 컬럼은 12개를 유지합니다.

스키마는 컬럼 이름·자료형·값의 역할처럼 표의 구조를 정한 것입니다. 이름이 같아도 단위나 의미가 다르면 같은 컬럼으로 취급해도 되는지 먼저 확인해야 합니다.

조식 행이 없는 것과 조식 칸이 빈 것은 다르다

네 학교의 표는 모두 같은 12컬럼이며 원래 빈 값이 없습니다. 그대로 다시 붙인 표에도 새 빈 값은 생기지 않습니다.

세현고에 석식 기록이 없다는 것은 ‘학교명=세현고등학교, 식사종류=석식’인 행이 없다는 뜻입니다. 식사종류 컬럼 자체가 비어 있는 것은 아닙니다.

학교마다 조·중·석을 모두 기록한다는 가정으로 해석하면 틀립니다. 다음 차시에는 날짜를 맞추어 가로로 붙일 때 생기는 실제 빈 셀을 관찰합니다.

7차시 준비 셀 뒤에서 실행합니다. 저장 파일을 나누는 대신 메모리 안에서 학교별 표를 만듭니다.

school_names = ["동양고등학교", "명덕고등학교", "영일고등학교", "세현고등학교"]
parts = {name: meals.loc[meals["학교명"].eq(name)] for name in school_names}
for name, table in parts.items():
    print(name, table.shape)
    print("식사종류:", sorted(table["식사종류"].unique()))

같은 컬럼, 늘어나는 행

selected_schools = school_names
combined = pd.concat([parts[name] for name in selected_schools], ignore_index=True)
print("합친 표:", combined.shape)
display(combined["학교명"].value_counts())
print("빈 셀 수:", combined.isna().sum().sum())

전체 네 학교이면 (1504, 12), 빈 셀 0개입니다. 선택 목록을 명덕고·세현고 두 학교로 바꾸면 몇 행이 될까요? Orange3에서도 같은 두 입력만 연결해 비교합니다.

  • 입력 순서를 바꾸면 행의 순서는 바뀔 수 있습니다. 학교별 건수와 값까지 달라졌는지 구별합니다.
  • 명덕고만 조식이 있고, 동양·영일고는 중식·석식, 세현고는 중식만 있는 것을 확인합니다.

“행은 붙일 수 있지만 학교마다 운영 방식이 같다”는 결론은 낼 수 없습니다. 다음 활동을 위해 네 학교를 모두 선택한 상태로 되돌립니다.

이번 주 3차시 · 9차시

Merge · 키로 다른 정보를 가로로

01 질문 제기

“학교는 4행, 급식은 1,504행인데 첫 행끼리 붙이면 될까?”

학교의 주소를 각 급식 기록에 붙이고 싶습니다. 어느 학교의 급식인지를 알려 주는 컬럼을 두 표에서 찾아봅시다.

날짜를 기준으로 두 학교를 비교할 때, 한 학교에만 있는 날짜는 결과에 남겨야 할까요?

02 Orange3에서 결과 확인

  1. meals.csv와 schools.csv를 각각 File로 읽습니다. 양쪽 표준학교코드를 String·Meta로 맞춥니다.
  2. 학교 표 뒤에 Select Columns를 연결해 표준학교코드·설립구분·도로명주소만 남깁니다. String 컬럼은 Meta에 두고 다른 컬럼은 Available로 옮깁니다.
  3. Merge Data의 Data에는 급식 표, Extra Data에는 학교 표를 연결합니다.
  4. 양쪽 표준학교코드를 매칭 조건으로 지정하고 Append columns from Extra Data를 선택합니다. Row index로 맞추지 않습니다.

Data Table에서 1,504행이 유지되고 각 급식 행에 맞는 학교 주소와 설립구분이 붙는지 확인합니다. 같은 코드가 학교 표에는 한 번, 급식 표에는 여러 번 있습니다.

이번 비교의 한 행은 학교별 하루 중식

  1. meals.csv의 File에서 Select Rows 두 개로 나눕니다. 각각 학교명=동양고등학교 AND 식사종류=중식, 학교명=세현고등학교 AND 식사종류=중식으로 정합니다.
  2. 각 Matching Data 뒤에 Select Columns를 두고 급식일자·급식인원만 남깁니다. 급식일자는 양쪽 같은 자료형을 유지합니다.
  3. Edit Domain에서 급식인원 이름만 각각 동양고_중식인원, 세현고_중식인원으로 바꿉니다. 값은 바꾸지 않습니다.

동양고 180행, 세현고 159행입니다. 중식만 고른 두 표는 날짜가 한 번씩만 나옵니다. 조·중·석을 모두 둔 표를 날짜만으로 연결하면 같은 날짜의 여러 식사가 서로 중복 연결될 수 있습니다.

이 차시의 Select Rows도 앞 차시처럼 두 가지 불필요 값·상수 컬럼 제거 옵션을 끕니다. 값이 일정한 컬럼도 비교 자료에 남겨 둡니다.

Data=동양고, Extra Data=세현고

새 Merge Data에 위 두 표를 연결하고 매칭 조건을 양쪽 급식일자로 지정합니다. 아래 모드를 하나씩 바꾸어 Data Table에서 행 수와 빈 칸을 기록합니다.

Orange3의 선택 이름과 확인할 결과

bike-daily.csv의 File 하나를 Select Columns 두 개로 나눕니다. 한쪽은 날짜·요일·공휴일여부·대여건수, 다른 쪽은 날짜·평균기온·최고기온·최저기온·강수량을 남깁니다.

지금은 완성된 배포 파일에서 컬럼을 나누어 원리를 재현합니다. 수천만 원본 행을 다시 집계하는 실습은 아닙니다. 강수량에 원래 있던 빈 값도 그대로 두고 확인합니다.

03 개념에 이름 붙이기

Merge는 키 값이 같은 행을 찾아 서로 다른 컬럼의 정보를 옆으로 붙이는 결합입니다. 키는 연결할 대상을 판단하는 기준 컬럼 또는 컬럼의 조합입니다.

학교 표의 표준학교코드는 학교마다 하나인 식별값입니다. 급식 표에서는 같은 학교의 여러 날·식사에서 반복됩니다. 이처럼 여러 급식 기록에 하나의 학교 정보를 붙일 수 있습니다.

급식 행 자체를 구별하려면 학교코드·급식일자·식사코드를 함께 봅니다. 키의 자료형과 의미, 어느 쪽에서 중복되는지를 확인해야 합니다.

연결되지 않는 행을 어디까지 남길 것인가

Merge 방식의 기준
방식남기는 키짝이 없을 때
inner양쪽에 모두 있는 키결과에 포함하지 않음
left왼쪽 표에 있는 키오른쪽 정보가 빈 값
outer양쪽 어느 곳에든 있는 키없는 쪽의 정보가 빈 값

left는 어느 표를 왼쪽에 놓는지가 중요합니다. Merge는 열을 붙이는 작업이지만, 방식과 키의 중복에 따라 행 수도 달라질 수 있습니다.

행이 없던 자리에 빈 셀이 나타난다

세현고의 마지막 기록은 2024-12-30입니다. 다음 날인 2024-12-31에는 동양고 중식 380명만 기록되어 있어 outer 결과의 세현고 인원이 빈 값입니다.

반대로 2024-05-07에는 세현고 중식 510명만 있어 동양고 인원이 빈 값입니다. 날짜가 다른 두 기록을 행 순서로 맞추면 같은 날처럼 잘못 비교하게 됩니다.

이 빈 값은 입력 CSV의 빈 셀과 다르게 매칭할 기록이 없어서 생긴 값입니다. 이번 주에는 발생 위치와 이유만 기록합니다. 채우거나 지우는 판단은 4주차에 합니다.
