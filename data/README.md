# 실습 데이터 안내

내용 기준은 [CURRICULUM.md](../docs/CURRICULUM.md)이다. **사용자가 원본 CSV 13개를 처리하고 품질을 확인했다(약 3,800만 행, 이용건수 결측 행 제외 0건, 음수 0건).** 최종 기간을 353일로 줄이는 코드·문서 수정만 반영했으며, 후속 지시에 따라 재실행은 사용자가 수행한다. 이 코드 수정 작업에서 배포 CSV를 재생성하지 않았으며 최종 커밋 대상 확정은 사용자 재실행 결과 확인 후에 한다.

## 학기 공통 파일

- 경로: `data/weather-bike/bike-daily.csv`
- 최종 대상 기간: **2024-03-01 ~ 2025-02-16**, 양 끝 포함 353일.
- 한 행: 날짜별 **서울 전체** 공공자전거 대여건수와 서울(108) 기상 관측값. 대여소별·시간대별 행은 최종 파일에 두지 않는다.
- 형식: 쉼표 구분, UTF-8 BOM(`utf-8-sig`), 날짜 오름차순, 인덱스 열 없음. 결측은 빈 필드.
- 353행은 변경된 날짜 기준표의 설계값이다. 가짜 관측값이나 예시 행을 만들지 않는다.

**기간을 2025-02-16까지로 줄인 이유:** 202502 따릉이 원본에 2월 16일 이후의 데이터가 없으며 재다운로드해도 동일하다고 사용자가 확인했다. 2월 17~28일은 집계 오류로 누락된 것이 아니라 원본 자체가 없는 기간이다. 기존 중간 파일은 유지하고 build-bike-daily.py에서 최종 기간만 선택해 병합한다. 이로써 대여건수가 비어 있던 마지막 12일을 최종 대상에서 제외한다.

압축 파일은 사용자가 풀어서 CSV만 해당 폴더에 둔다. 월별 원본은 한 달에 한 파일을 전제로 한다. 여러 달을 합친 파일이나 같은 달의 중복·분할 파일이 있으면 먼저 파일 구성과 합계 중복 여부를 확인해야 한다. 파일 이름은 강제하지 않으며 월은 원본 날짜 열로 판별한다.

`/source/`와 `/work-temp/`는 Git에서 제외한다. 2.5단계 후속 확인에서 원본 CSV 13개 모두 제외 대상이며 source/의 스테이징·추적 파일은 0개였다. 원본은 디스크에 보존한다. 이 처리 흐름의 CSV 커밋 후보는 `data/weather-bike/bike-daily.csv` 하나이며, `data/weather-bike/`의 다른 CSV도 제외한다.

이후 4~5주차 실습용 처리 단계별 CSV를 추가할 때는 해당 파일이 커밋 대상이 되도록 `.gitignore`도 수정해야 한다.

2026-09-09에 각 파일의 앞 4,096바이트를 읽어 cp949로 헤더가 해석되는 것을 확인했다. 전체 파일 디코딩·내용 검증 결과는 아니다. 스크립트는 UTF-8 BOM·cp949·euc-kr 및 BOM이 있는 UTF-16을 확인하고 앞쪽 안내·주석 행 다음의 헤더를 찾는다. 잘못된 문자를 대체하거나 오류 행을 무시하고 진행하지 않는다. 실제 내려받은 날짜와 이용 조건은 사용자가 아래 수집 기록에 남긴다.

## 공휴일 기준과 출처

**사용자가 대조·확인한 HOLIDAYS의 19개 날짜만** 공휴일여부=1로 표시한다. 일요일이라는 이유만으로 공휴일에 추가하지 않는다. 일요일 정보는 요일 열에 있으며, 회귀에서 일요일 효과와 공휴일 효과를 구분하기 위한 정의이다. 일요일 포함 옵션은 제거했다. HOLIDAYS에 있는 날짜는 일요일과 겹치더라도 공휴일로 표시한다. 이후 연도의 제도 변경을 소급 적용하지 않는다.

| 연도 | HOLIDAYS에 지정된 날짜 |
|---|---|
| 2024 | 03-01, 04-10(국회의원 선거), 05-05, 05-06(대체), 05-15, 06-06, 08-15, 09-16~18, 10-01(임시), 10-03, 10-09, 12-25 |
| 2025 | 01-01, 01-27(임시), 01-28~30 |

근거: [2024년도 월력요항](https://www.kasi.re.kr/kor/publication/post/newsMaterial/29633?cPage=7), [2025년도 월력요항 발표 수록](https://www.kasi.re.kr/publication/post/newsMaterial?cPage=10), [2024년 5월 일력](https://astro.kasi.re.kr/file/astro_almanac_pdf/20231023135218580.pdf), [2024-10-01 임시공휴일 지정](https://www.korea.kr/news/policyNewsView.do?newsId=148933400), [2025-01-27 임시공휴일 지정](https://www.korea.kr/news/policyNewsView.do?newsId=148938559).

외부 달력 패키지를 설치하거나 API를 실행 중 호출하지 않는다. 기간이 변경되면 `HOLIDAYS`와 `HOLIDAY_COVERAGE`도 함께 확인해야 한다.

## 원본 컬럼명 대조표

ASOS 원본 순서는 `지점, 지점명, 일시, 평균기온(°C), 최저기온(°C), 최고기온(°C), 일강수량(mm)`이다. 위치가 아니라 이름으로 매핑하므로 최저기온이 최고기온보다 먼저 있어도 바뀌지 않는다. 기상 4개 열은 아래 부분 문자열을 찾고, 날짜·지점과 따릉이 열은 이름 후보로 찾는다. °·℃ 등 단위 문자를 매칭 조건에 넣지 않는다. 헤더 공백·BOM은 무시하고 후보가 둘 이상이면 임의 선택하지 않고 중단한다. 현재 따릉이 12개 파일 모두에서 `대여일자`, `이용건수`를 확인했다.

따릉이 원본의 부가 열은 연도에 따라 다르다. 2024년 파일에는 `이동거리(M)`, `이용시간(분)`이 있고 2025년 1~2월 파일에는 `이동거리`가 있다. 집계 스크립트는 날짜와 이용건수만 읽으므로 이 차이로 매핑을 바꿀 필요는 없다.

| 스크립트 | 정리할 열 | 현재 원본 컬럼 후보 |
|---|---|---|
| prepare-weather.py | 날짜 | 일시 / 날짜 / 관측일자 |
| prepare-weather.py | 평균기온 | 평균기온 (부분 문자열) |
| prepare-weather.py | 최저기온 | 최저기온 (부분 문자열) |
| prepare-weather.py | 최고기온 | 최고기온 (부분 문자열) |
| prepare-weather.py | 강수량 | 일강수량 (부분 문자열) |
| prepare-weather.py | 지점(선택) | 지점 / 지점번호 / 관측지점번호 |
| aggregate-bike.py | 날짜 | 대여일자 / 대여일시 / 기준일자 / 날짜 |
| aggregate-bike.py | 대여건수 | 이용건수 / 대여건수 / 이용 건수 / 대여 건수 |

ASOS의 지점 열이 있으면 108만 선택한다. 지점 열이 없으면 콘솔에 확인 요청을 출력하므로 사용자가 다운로드 지점을 확인해야 한다. 대여소 번호, 대여 시간, 성별·연령·이용권 등의 열은 집계 기준으로 쓰지 않는다. 소계·합계 행과 상세 행이 함께 들어 있는 자료는 이중 집계가 될 수 있으므로 사용 전에 원본의 행 의미를 반드시 대조한다.

`build-bike-daily.py`는 원본을 다시 읽지 않고 다음 중간 결과만 기대한다.

- 기상: 날짜, 평균기온, 최고기온, 최저기온, 강수량
- 따릉이: 날짜, 대여건수

## 실행 순서

**이번 기간 축소는 코드·문서 수정만 수행하며 사용자가 재실행한다.** 원본 집계와 중간 파일 준비는 완료되어 이번에는 아래 3번 build-bike-daily.py만 실행하면 된다. 처음부터 데이터를 준비할 때는 세 단계를 순서대로 실행한다. Python 3.10 이상과 pandas가 필요하며, pandas 외 외부 Python 패키지는 사용하지 않는다. pandas가 없다면 사용할 Python 환경에 pandas만 설치한다.

64비트 Python 환경에서 다음과 같이 준비한다. pandas의 필수 하위 의존성은 pip가 함께 설치하며 별도 달력·CSV 패키지는 추가하지 않는다. [pandas 공식 설치 안내](https://pandas.pydata.org/docs/getting_started/install.html).

```powershell
py -3 --version
py -3 -m pip install pandas
```

저장소 루트의 PowerShell 기준:

```powershell
py -3 scripts/prepare-weather.py
if ($LASTEXITCODE -ne 0) { throw "기상 정리 실패: 다음 단계를 실행하지 마세요." }
py -3 scripts/aggregate-bike.py
if ($LASTEXITCODE -ne 0) { throw "따릉이 집계 실패: 다음 단계를 실행하지 마세요." }
py -3 scripts/build-bike-daily.py
if ($LASTEXITCODE -ne 0) { throw "최종 병합 실패: 오류를 확인하세요." }
```

Python 실행 명령이 `python`인 환경에서는 `py -3`을 `python`으로 바꾼다. 경로 기본값은 스크립트 위치를 기준으로 계산한다.

py 런처가 설치된 Python을 찾지 못하면 PowerShell에서 `& "설치된 python.exe의 전체 경로" scripts/build-bike-daily.py`로 실행한다. 이 세션에서는 Python이나 pandas 설치 여부를 추가로 검사하거나 스크립트를 실행하지 않는다.

| 단계 | 처리 | 결과 |
|---|---|---|
| 1 · prepare-weather.py | 헤더·인코딩 확인 → 서울(108)·기간 선택 → 날짜·기온 3종·일강수량 정리 | `work-temp/data-preparation/weather-daily.csv` |
| 2 · aggregate-bike.py | 월별 12개 순차 처리 → 파일별 100,000행 청크 → 날짜별 이용건수 합산 | `work-temp/data-preparation/bike-counts-daily.csv` |
| 3 · build-bike-daily.py | 중간 파일에서 2024-03-01~2025-02-16 선택 → 353일 날짜표에 1:1 왼쪽 병합 → 요일·공휴일 추가 | `data/weather-bike/bike-daily.csv` |

[공통 읽기 모듈 csvtools.py](../scripts/csvtools.py)는 인코딩·헤더 탐색, 날짜/수치 변환, 결측 요약과 저장을 공유한다. 별도로 실행하지 않는다. 중간 결과는 Git 제외 영역에 두며 최종 파일만 검토 후 배포한다. 재실행하면 해당 출력 파일을 교체하지만 원본에는 쓰지 않는다.

각 실행이 성공한 뒤 결측 개수와 컬럼별 요약을 확인한다. 앞 단계가 실패했다면 중단하고 원인을 수정한 후 그 단계부터 다시 실행한다. 이전 실행의 중간 결과가 남아 있을 수 있으므로 실패 후 바로 다음 단계를 실행하지 않는다.

### 단계별 성공 기준

모든 단계에서 현재 실행의 종료 코드가 0이고 마지막에 `[저장]`과 대상 경로가 출력되어야 한다. 파일이 이미 있다는 사실만으로 성공을 판정하지 않는다. 결측은 0개일 필요가 없다.

| 단계 | 확인할 내용 |
|---|---|
| 기상 정리 | weather-daily.csv에 날짜·평균기온·최고기온·최저기온·강수량 5열. 서울(108), 기간 내 날짜, 중복 날짜 0개. 강수량 공백은 빈 필드로 유지. 원본 날짜가 빠져 있으면 365행보다 적을 수 있음 |
| 따릉이 집계 | bike-counts-daily.csv에 날짜·대여건수 2열. 12개 월 모두 처리, 날짜별 최대 1행. 결측 행을 제외하고 유효한 이용건수를 합산하며 하루의 모든 행이 결측인 경우에만 빈 필드. 월별 제외 행 수, 전체 제외 행 수·비율, 대여건수 결측 날짜 목록 출력 |
| 최종 병합 | bike-daily.csv에 2024-03-01~2025-02-16 날짜 353행·지정 순서의 8열, UTF-8 BOM. 날짜 연속·중복 없음, 강수량 외 결측 0개인지 확인하고 대여건수 최소·최대 보고. HOLIDAYS 19개 날짜만 공휴일로 표시. 컬럼별 결측 요약과 최종 대여건수 결측 날짜 목록 출력 |

### 실패 시 확인할 곳

| 증상 | 흔한 원인·대처 |
|---|---|
| Python 없음 / py 명령 인식 실패 | Python 3.10 이상 설치·경로 확인. python 명령을 쓰면 설치와 실행 양쪽 모두 같은 명령으로 바꿈 |
| No module named pandas | 스크립트를 실행할 Python으로 `py -3 -m pip install pandas` 실행. 다른 Python에만 설치하지 않았는지 확인 |
| 필수 컬럼 없음 / 후보 여러 개 | COLUMN_MAP과 SUBSTRING_COLUMNS 대조. 기온 열과 QC·시각 열이 함께 매칭되면 검색어를 구체화하거나 해당 열만 정확 비교하도록 설정 |
| UnicodeDecodeError / 헤더 탐색 실패 | prepare-weather.py의 ENCODING·HEADER_ROW·DELIMITER, 또는 aggregate-bike.py의 FILE_OVERRIDES 확인. header_row는 0부터 셈. UTF-8/cp949 등 실제 인코딩을 지정하고 오류 문자를 임의 삭제하지 않음 |
| 월별 CSV 12개 불일치 / 중복 월 / 여러 달 포함 | ZIP을 풀었는지, 한 달에 한 CSV인지, 202403~202502가 각각 있는지 확인. 분할본·합계본을 무작정 함께 넣지 않음 |
| 날짜·숫자 변환 실패 / 정수가 아닌 이용건수 | 오류 컬럼의 각주·합계 행·날짜 형식·단위·특수 결측 부호를 확인. 원본을 임의로 지우거나 0으로 바꾸지 말고 제공 기관 정의에 맞게 파싱 규칙을 조정 |
| 메모리 부족 | 64비트 Python 확인, CHUNK_SIZE를 100_000에서 20_000 등으로 낮춤. 전체 CSV를 합쳐 한꺼번에 읽지 않음 |
| PermissionError / 저장 실패 | 출력 CSV를 열어 둔 Excel 등을 닫고 경로 권한 확인. 실패 후 이전 파일을 새 결과로 사용하지 않음 |

헤더 탐색은 표준 라이브러리 csv.reader, 데이터 본문은 pandas.read_csv에 맡긴다. quotechar·quoting·doublequote를 재설정하거나 큰따옴표를 수동 제거하지 않는다. 대여소명에 쉼표가 있어도 표준 CSV의 인용 규칙으로 읽는다. 숫자 열 안의 천 단위 쉼표 정리는 CSV 파싱 후에만 수행한다. [pandas read_csv 문서](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html).

## 결측·이상치를 남기는 이유와 처리 범위

**4~5주차 실습을 위해 결측을 의도적으로 보존한다.** 결측을 인위적으로 만드는 것은 아니다.

### 강수량 결측 212개의 의미 — 축소 전 365일 기준

사용자의 원본 검토에 따르면 **기존 365일 중 강수량 결측 212일은 비가 오지 않은 날**이다. 원본에서 무강수일을 공백으로 남겼으며 일부 무강수일은 수치 0으로 기록해 두 표현이 혼재한다. 따라서 이 파일에서 해당 결측의 실제 의미는 **강수량 0 mm**이다. 212개는 축소 전 기간의 수치이며 353일 결과의 결측 개수로 그대로 인용하지 않는다.

이는 **4주차 결측치 실습의 핵심 소재**이다. 학생이 이 결측을 평균으로 채우면 비가 오지 않은 날에 강수량을 만들어 넣게 되고, 해당 행을 삭제하면 유효한 무강수일 관측을 잃는다. 두 방법 모두 이 자료에서는 잘못된 처리다. 출처·기록 방식·데이터 맥락을 알아야 올바르게 결측을 처리할 수 있음을 가르친다.

실제 의미가 0임을 확인했더라도 **스크립트 단계에서는 이 결측을 채우지 않는다.** 원본 공백과 명시적인 0을 그대로 보존하고, 학생이 맥락을 확인한 뒤 처리 방법을 선택하는 활동에 남긴다.

- 강수량의 원본 공백은 결측으로, 원본에 기록된 수치 0은 0으로 유지한다.
- 기온·강수량·대여건수의 이상치를 제거하거나 보정하지 않는다. 음수·큰 수 등도 수치로 해석할 수 있으면 유지한다.
- 대여건수는 결측인 원본 행을 합산에서 제외하고 나머지 유효한 값으로 일별 합계를 계산한다. 그날의 모든 행이 결측인 경우에만 대여건수를 비워 둔다. 유효한 0이나 합계 0은 결측으로 바꾸지 않는다. 청크 경계를 넘어도 같은 규칙을 적용한다.
- 강수량은 독립변수·4주차 결측 실습 소재이므로 원본 결측을 그대로 보존한다. 회귀의 종속변수인 대여건수에는 위의 유효값 합산 정책을 적용한다.
- 월별로 합산에서 제외한 이용건수 결측 행 수를 출력한다. 전체 제외 비율의 분모는 12개 파일에서 읽은 데이터 행 수이며 헤더·빈 줄은 포함하지 않는다. 전체 제외 행 수·비율과 하루 전체가 결측인 날짜 목록을 출력하고, 마지막 병합 단계에서는 원본 행이 없는 날짜까지 포함한 최종 결측 날짜를 출력한다.
- 원본 날짜 행이 통째로 없으면 최종 파일에서 해당 관측 열을 비워 둔다. 일별 파일만으로 대여소·시간대 일부 행의 누락까지 자동 판정할 수는 없다.
- 빈 필드와 명시된 NA/N/A/NaN/NULL/None만 결측으로 읽는다. `-`, `-999`, `-9999` 같은 부호는 제공 기관 정의를 확인하기 전까지 임의 결측 처리하지 않는다. 숫자인 부호는 그대로 남고 숫자가 아닌 미정 부호는 오류로 알린다.
- 잘못된 날짜, 소계·각주, 중복 기상 날짜, 중복 월, 정수가 아닌 건수 등은 조용히 삭제·반올림하지 않고 중단한다.
- 출력에는 결측 개수와 모든 컬럼의 요약을 인쇄한다. 기간 축소 후 최종 결측 개수는 사용자 재실행 결과로 확정하며 가짜 결측을 만들지 않는다.
