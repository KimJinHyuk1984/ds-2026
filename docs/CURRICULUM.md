## 3. 실습 데이터

교과서의 실습 데이터(붓꽃, 유방암, 동물원, 키_몸무게, 공부시간-성적, 제주도 관광코스)는 **사용하지 않는다.**
학생이 실생활에서 접하는 소재로 전면 교체한다.

### 3-1. 데이터 3종과 담당 구간

| 데이터 | 출처 | 담당 구간 | 선정 이유 |
|---|---|---|---|
| **NEIS 학교 데이터** | NEIS 교육정보 개방 포털 (학교기본정보, 급식식단정보) | 2주차 수집 · 3주차 통합 · 13주차 연관분석 | API 호출을 파이썬으로 하므로 수집 단원 전체가 파이썬 실습이 된다. 자기 학교 데이터라 몰입도가 높다. |
| **기상 + 따릉이** | 기상청 ASOS 일자료 + 서울 열린데이터광장 따릉이 대여이력 | 1주차 따릉이 일별 CSV · 3주차 기상 통합 · 4~6주차 전처리 · 7~8주차 통계·시각화 · 9~11주차 회귀 | 결측치·이상치가 실제로 존재하고, 두 파일 결합(Merge)이 필연적이다. 회귀 성능이 적절히 나온다. |
| **KBO 선수 기록** | 공개 기록 데이터 | 12주차 분류 · 13주차 군집 | 포지션 분류, 선수 유형 군집이 교과서적으로 잘 맞아떨어진다. 지표가 많아 상관분석에도 유리하다. |

### 3-2. 회귀 과제 정의

**입력**: 일평균기온, 최고기온, 강수량, 요일, 공휴일 여부
**출력**: 해당 일자의 따릉이 대여 건수

기온 자체를 예측하는 것은 시계열 문제이므로 이 과정에서 다루지 않는다.
입력 변수를 단계적으로 늘려가며(기온만 → 기온+강수 → +요일) R²의 변화를 관찰하는 것이 핵심 활동이다.

### 3-3. 연관분석 과제 정의

NEIS 급식식단정보의 메뉴 텍스트를 장바구니(transaction) 형태로 변환하여 메뉴 간 연관 규칙을 도출한다.
예: "돈까스가 나오는 날에는 우동이 함께 나온다"

### 3-4. 1주차와 최종 프로젝트 데이터 (사용자 확정)

- 1주차는 **따릉이 일별 대여 건수 CSV를 그대로 사용**한다. Orange3 내장 데이터는 사용하지 않는다.
- 14~15주차는 **NEIS / 기상·따릉이 / KBO 중 택1**을 기본으로 한다.
- 14~15주차에는 **공공데이터포털에서 직접 수집한 데이터도 허용**한다. 다른 주차의 지정 데이터는 변경하지 않는다.
- 위 허용은 교재 실습 데이터 사용 금지를 해제하지 않는다.

### 3-5. 데이터 준비 시 주의

- 따릉이 대여이력 원본은 월 단위 수백만 행으로 Orange3가 처리하지 못한다.
  **교사가 사전에 일별로 집계한 CSV(수백~수천 행)를 배포**한다.
- 배포용 CSV는 저장소 `data/` 디렉터리에 둔다.
- 원본 수집·집계 스크립트는 `scripts/` 디렉터리에 둔다.


### 3-6. 학기 공통 bike-daily.csv 사양 (2.5단계 사용자 확정)

- 최종 경로: `data/weather-bike/bike-daily.csv`.
- 최종 기간: **2024-03-01 ~ 2025-02-16**, 양 끝 포함 353일. 202502 따릉이 원본은 재다운로드해도 2월 16일 이후 데이터가 없어 기간을 줄인다. 원본 준비 범위와 기존 중간 파일은 유지하고 최종 병합에서 기간만 선택한다. 관측값을 만들어 채우지 않는다.
- 집계: 날짜별 서울 전체 대여건수 합계. 대여소·시간대별로 최종 행을 나누지 않는다.
- 기상: 기상청 ASOS **서울(108)** 일자료.
- 최종 컬럼 순서: **날짜, 요일, 공휴일여부, 평균기온, 최고기온, 최저기온, 강수량, 대여건수**.
- 원본은 사용자가 직접 내려받는다. ASOS CSV 1개는 `source/weather/`, 시간대별 공공자전거 이용정보 월별 CSV 12개는 `source/bike/`에 둔다.
- `prepare-weather.py` → `work-temp/data-preparation/weather-daily.csv`, `aggregate-bike.py` → `work-temp/data-preparation/bike-counts-daily.csv`, `build-bike-daily.py` → 최종 배포 CSV 순서로 처리한다.
- 2.5단계 최초 작업은 스크립트 작성만 수행했다. 이후 사용자가 원본 집계·품질 확인과 기간 축소 후 재실행·최종 검증을 완료했다. 현재 배포 파일은 353행 × 8열, 날짜 누락 0일, 강수량 결측 200개, 대여건수 결측 0개, 공휴일 19일로 확정한다. 원본·가짜·샘플 CSV를 만들지 않으며 외부 Python 의존성은 pandas만 사용한다.
- 강수량의 공백·결측을 0으로 바꾸지 않는다. 수치형 이상치의 제거·보정·클리핑·대체도 하지 않는다. 결측 처리는 4주차 학생 실습에 남긴다.
- 사용자 확인: 현재 배포 파일 353일의 강수량 결측은 200개다. 축소 전 365일에는 212개였으며, 잘라낸 12일(2025-02-17~2025-02-28)이 모두 무강수일이고 강수량이 공백이어서 12개 줄었다. 원본의 공백과 명시적인 0이 혼재하며 결측의 실제 의미는 0이지만 스크립트에서 채우지 않는다. 학생이 평균 대체나 행 삭제를 적용하면 잘못된 처리가 되는 사례로, 데이터 맥락을 확인하는 4주차 핵심 실습에 사용한다.
- 대여건수는 행 개수가 아니라 원본 건수 열의 합이다. 이용건수가 결측인 행은 합산에서 제외하고 나머지 값으로 일별 합계를 계산한다. 그날의 모든 행이 결측일 때만 대여건수를 결측으로 남긴다. 날짜 행 자체가 없는 날도 최종 날짜 기준표에서 관측값을 결측으로 유지한다. 월별 제외 행 수, 전체 제외 행 수·비율, 대여건수 결측 날짜 목록을 콘솔에 출력한다. 강수량 결측 보존과 대여건수 유효값 합산은 구분한다.
- 최종 CSV는 UTF-8 BOM으로 저장하고 결측은 빈 필드로 기록한다. 각 단계 실행 후 결측 개수와 컬럼별 요약을 콘솔에 출력한다. 사용자 재실행으로 2024-03-01~2025-02-16의 353행 × 8열, 날짜 누락 0일, 강수량 결측 200개, 대여건수 결측 0개, 공휴일 19일을 확정했으며 결측을 인위적으로 만들지 않는다.
- 요일은 월~일, 공휴일여부는 1/0이다. 사용자가 확인한 HOLIDAYS 19개 날짜만 공휴일로 표시한다. 일요일 자체는 추가하지 않고 일요일 포함 옵션도 두지 않는다. 요일과 공휴일여부를 회귀 입력으로 함께 사용해 각 효과를 구분한다. 날짜 목록과 근거는 `data/README.md` 및 `build-bike-daily.py`에 기록한다.

## 6. 사이트 제작 규칙

### 6-1. 교재와의 관계

첨부된 교재 PDF는 **사용자 본인이 집필에 참여한 자료**이며, 성취기준·개념 설명 순서·용어 정의를 참고하는 용도로 사용한다.

단, 다음은 반드시 지킨다.

- 교재의 **이미지·도표·삽화를 추출하거나 재현하지 않는다** (출판사·외주 저작물이 포함되어 있음)
- 교재의 **레이아웃과 페이지 구성을 재현하지 않는다**
- 본문 문장을 그대로 옮기지 않고, 재구성안에 맞춰 **새로 작성**한다
- "교과서 웹 버전" 류의 표현을 사용하지 않는다
- 교재는 **쪽수 참조로만 연결**한다 (예: `관련 교재 p.67~80`)

### 6-2. 공통 요소

`lecture-template`의 공통 요소(강사 소개, 메뉴, 글꼴, 코드 표시 방식)는 그대로 재사용한다. 강의별로 새로 만들지 않는다.

### 6-3. 미완성 콘텐츠

- `levels`는 처음부터 15개를 유지하며 2단계에서는 **전부 `status: "coming"`**으로 둔다. 1주차도 3단계 본문 완성 후 `ready`로 바꾼다.
- `coming` 주차는 목록에 링크 없는 **준비 중 카드**로 표시한다.
- 2단계 개별 URL에는 주차 번호·제목·차시 범위·학습목표·사용 데이터·교재 쪽수·준비 중 안내·학기 홈 링크만 있는 완성된 안내 페이지를 둔다. 미완성 원고를 HTML에 숨겨 넣지 않는다.
- 사용자 승인 2.5단계에서는 1주차에 주차 안내·차시 구성 틀·Orange3 설치/실행·Colab 접속/기본 사용 안내만 추가한다. CSV 실습은 빈 자리로 남기고 status는 계속 coming이다.
- 주차 선택은 `ready`만 이동 가능하고, 이전·다음은 현재 주차도 `ready`인 경우에만 다른 `ready` 주차와 연결한다. `coming` 안내 페이지의 이전·다음은 비활성 상태이다.
- **GitHub Actions 선별 배포를 도입하지 않는다.** 빌드 없는 정적 파일 운영과 `.nojekyll`을 유지한다.

### 6-4. 확정된 사이트 구조와 데이터 배치

- B안: 학기 홈 `index.html` + 15개 주차 페이지 `week-01/index.html` ~ `week-15/index.html`.
- 폴더명, `levels[].slug`, `body[data-level]`은 `week-01` ~ `week-15`로 일치시킨다. 주차 번호로 URL을 식별한다.
- `data/site.js`에는 15주 순서·제목·차시·사용 데이터·교재 쪽수·학습목표·공개 상태를 담는다. 내용 변경은 이 문서를 먼저 갱신한 뒤 메타데이터와 HTML에 반영한다.
- 공통 `shared.js`, `base.css`, `tokens.css`, `DESIGN.md`와 강사 정보는 그대로 사용한다. 주차 이동은 `widgets.js`, 스타일은 `lecture.css`에서 확장한다.
- 배포용 CSV는 데이터별 `data/neis/`, `data/weather-bike/`, `data/kbo/`에서 여러 주차가 공유한다. 14~15주차의 직접 수집 자료는 출처와 파일 범위를 확정한 후 `data/` 아래에 배치한다.
- `data/README.md`에 출처·수집 기간·컬럼·단위·가공 단계·사용 주차를 기록한다. 전처리 학습용과 처리 완료본은 구분하여 보존한다.
- 원본 수집·집계 스크립트는 `scripts/`에 둔다. 2단계에는 폴더와 기록 틀만 만들며 CSV·스크립트는 만들지 않는다.
- 학생은 주차의 상대 경로 다운로드 링크로 CSV를 받는다. CSV가 없는 준비 단계에는 다운로드 링크를 만들지 않는다. 이후 Colab에서도 같은 배포 CSV를 사용한다.

## 8. 1주차의 2.5단계 작성 범위

- 주차 안내: Orange3와 Colab을 함께 준비하고 같은 CSV를 두 도구에서 다룰 수업임을 안내한다. Python 문법을 재교육하지 않는다.
- 1차시: 두 도구 열기·환경 확인. 2차시: 같은 CSV 확인 자리. 3차시: 워크플로우 실행·결과 비교 자리. CSV가 필요한 상세 활동은 작성하지 않는다.
- Orange3: 공식 다운로드에서 운영체제에 맞는 설치 프로그램을 선택하고 실행한 뒤 빈 작업 화면을 확인한다. 내장 데이터나 예제 워크플로우를 실습 데이터로 사용하지 않는다.
- Colab: 공식 사이트 접속, 새 노트북 생성·이름 변경, 코드/텍스트 셀 구분, 런타임 연결, 실행 버튼, 저장 위치를 안내한다. 데이터 없이 연결을 확인하는 짧은 출력 코드만 둔다.
- 도구 안내 참고: [Orange 공식 설치 안내](https://orangedatamining.com/download/), [Orange 시작 안내](https://orangedatamining.com/getting-started/), [Google Colab FAQ](https://research.google.com/colaboratory/faq.html). 내용 구성은 이 문서를 기준으로 하며 외부 자료는 도구 조작 사실만 확인한다.
