### 3-2. 회귀 과제 정의

**입력**: 일평균기온, 최고기온, 강수량, 요일, 공휴일 여부
**출력**: 해당 일자의 따릉이 대여 건수

기온 자체를 예측하는 것은 시계열 문제이므로 이 과정에서 다루지 않는다.
입력 변수를 단계적으로 늘려가며(기온만 → 기온+강수 → +요일) R²의 변화를 관찰하는 것이 핵심 활동이다.

### 3-3. 연관분석 과제 정의

NEIS 급식식단정보의 메뉴 텍스트를 장바구니(transaction) 형태로 변환하여 메뉴 간 연관 규칙을 도출한다.
예: "돈까스가 나오는 날에는 우동이 함께 나온다"

### 3-4. 1주차와 최종 프로젝트 데이터 (사용자 확정)

- 1주차는 **따릉이 일별 대여 건수 CSV를 그대로 사용**한다. Orange3 내장 데이터는 사용하지 않는다.
- 14~15주차는 **NEIS / 기상·따릉이 / KBO 중 택1**을 기본으로 한다.
- 14~15주차에는 **공공데이터포털에서 직접 수집한 데이터도 허용**한다. 다른 주차의 지정 데이터는 변경하지 않는다.
- 위 허용은 교재 실습 데이터 사용 금지를 해제하지 않는다.

### 3-5. 데이터 준비 시 주의

- 따릉이 대여이력 원본은 월 단위 수백만 행으로 Orange3가 처리하지 못한다.
  **교사가 사전에 일별로 집계한 CSV(수백~수천 행)를 배포**한다.

### 3-6. 학기 공통 bike-daily.csv 사양 (2.5단계 사용자 확정)

- 최종 경로: `data/weather-bike/bike-daily.csv`.
- 최종 기간: **2024-03-01 ~ 2025-02-16**, 양 끝 포함 353일. 202502 따릉이 원본은 재다운로드해도 2월 16일 이후 데이터가 없어 기간을 줄인다. 원본 준비 범위와 기존 중간 파일은 유지하고 최종 병합에서 기간만 선택한다. 관측값을 만들어 채우지 않는다.
- 집계: 날짜별 서울 전체 대여건수 합계. 대여소·시간대별로 최종 행을 나누지 않는다.
- 기상: 기상청 ASOS **서울(108)** 일자료.
- 최종 컬럼 순서: **날짜, 요일, 공휴일여부, 평균기온, 최고기온, 최저기온, 강수량, 대여건수**.
- 원본은 사용자가 직접 내려받는다. ASOS CSV 1개는 `source/weather/`, 시간대별 공공자전거 이용정보 월별 CSV 12개는 `source/bike/`에 둔다.
- `prepare-weather.py` → `work-temp/data-preparation/weather-daily.csv`, `aggregate-bike.py` → `work-temp/data-preparation/bike-counts-daily.csv`, `build-bike-daily.py` → 최종 배포 CSV 순서로 처리한다.
- 2.5단계 최초 작업은 스크립트 작성만 수행했다. 이후 사용자가 원본 집계·품질 확인과 기간 축소 후 재실행·최종 검증을 완료했다. 현재 배포 파일은 353행 × 8열, 날짜 누락 0일, 강수량 결측 200개, 대여건수 결측 0개, 공휴일 19일로 확정한다. 원본·가짜·샘플 CSV를 만들지 않으며 외부 Python 의존성은 pandas만 사용한다.
- 강수량의 공백·결측을 0으로 바꾸지 않는다. 수치형 이상치의 제거·보정·클리핑·대체도 하지 않는다. 결측 처리는 4주차 학생 실습에 남긴다.
- 사용자 확인: 현재 배포 파일 353일의 강수량 결측은 200개다. 축소 전 365일에는 212개였으며, 잘라낸 12일(2025-02-17~2025-02-28)이 모두 무강수일이고 강수량이 공백이어서 12개 줄었다. 원본의 공백과 명시적인 0이 혼재하며 결측의 실제 의미는 0이지만 원본 준비 스크립트에서는 채우지 않는다. 별도 수업 후 정제본 생성은 11절을 따른다. 학생이 평균 대체나 행 삭제를 적용하면 잘못된 처리가 되는 사례로, 데이터 맥락을 확인하는 4주차 핵심 실습에 사용한다.
- 대여건수는 행 개수가 아니라 원본 건수 열의 합이다. 이용건수가 결측인 행은 합산에서 제외하고 나머지 값으로 일별 합계를 계산한다. 그날의 모든 행이 결측일 때만 대여건수를 결측으로 남긴다. 날짜 행 자체가 없는 날도 최종 날짜 기준표에서 관측값을 결측으로 유지한다. 월별 제외 행 수, 전체 제외 행 수·비율, 대여건수 결측 날짜 목록을 콘솔에 출력한다. 강수량 결측 보존과 대여건수 유효값 합산은 구분한다.
- 최종 CSV는 UTF-8 BOM으로 저장하고 결측은 빈 필드로 기록한다. 각 단계 실행 후 결측 개수와 컬럼별 요약을 콘솔에 출력한다. 사용자 재실행으로 2024-03-01~2025-02-16의 353행 × 8열, 날짜 누락 0일, 강수량 결측 200개, 대여건수 결측 0개, 공휴일 19일을 확정했으며 결측을 인위적으로 만들지 않는다.
- 요일은 월~일, 공휴일여부는 1/0이다. 사용자가 확인한 HOLIDAYS 19개 날짜만 공휴일로 표시한다. 일요일 자체는 추가하지 않고 일요일 포함 옵션도 두지 않는다. 요일과 공휴일여부를 회귀 입력으로 함께 사용해 각 효과를 구분한다. 날짜 목록과 근거는 `data/README.md` 및 `build-bike-daily.py`에 기록한다.

## 5. Orange3 – Python 병행 원칙

기본적으로 **오렌지로 먼저 결과를 확인한 뒤 같은 결과를 파이썬으로 재현**한다. 6주차 프로젝트는 산출물 제작 중심으로 운영하며 이 순서를 적용하지 않는다. 사용자 확정 예외인 5주차 13차시는 Python이 문자열 분리·행 확장을 주도하고 Orange3에서 결과를 대조한다. 4주차 LOF와 IQR처럼 탐지 기준이 다른 경우에는 결과 일치보다 기준과 해석을 비교한다.

학생들이 문법을 이미 학습했으므로, 빈칸 채우기 노트북이 아니라
**동작하는 완성 코드를 제공하고 조건·변수를 바꿔가며 결과 변화를 관찰**하게 한다.
6주차 프로젝트에서는 학생이 직접 작성하며, 원본 CSV 읽기와 선택용 한글 폰트 준비 외에 정답 코드를 제공하지 않는다.

## 6. 사이트 제작 규칙

### 6-1. 교재와의 관계

첨부된 교재 PDF는 **사용자 본인이 집필에 참여한 자료**이며, 성취기준·개념 설명 순서·용어 정의를 참고하는 용도로 사용한다.

단, 다음은 반드시 지킨다.

- 교재의 **이미지·도표·삽화를 추출하거나 재현하지 않는다** (출판사·외주 저작물이 포함되어 있음)
- 교재의 **레이아웃과 페이지 구성을 재현하지 않는다**
- 본문 문장을 그대로 옮기지 않고, 재구성안에 맞춰 **새로 작성**한다
- "교과서 웹 버전" 류의 표현을 사용하지 않는다
- 교재는 **쪽수 참조로만 연결**한다 (예: `관련 교재 p.67~80`)

### 6-2. 공통 요소

`lecture-template`의 공통 요소(강사 소개, 메뉴, 글꼴, 코드 표시 방식)는 그대로 재사용한다. 강의별로 새로 만들지 않는다.

### 6-3. 미완성 콘텐츠

- `levels`는 처음부터 15개를 유지하며 2단계에서는 **전부 `status: "coming"`**으로 둔다. 1주차도 3단계 본문 완성 후 `ready`로 바꾼다.
- `coming` 주차는 목록에 링크 없는 **준비 중 카드**로 표시한다.
- 2단계 개별 URL에는 주차 번호·제목·차시 범위·학습목표·사용 데이터·교재 쪽수·준비 중 안내·학기 홈 링크만 있는 완성된 안내 페이지를 둔다. 미완성 원고를 HTML에 숨겨 넣지 않는다.
- 2.5단계에서는 1주차의 설치·접속 안내만 먼저 작성했다. 사용자 승인 3단계에서는 아래 8절에 따라 1주차 본문과 CSV 실습을 완성하고 `week-01`만 `ready`로 전환한다. 나머지 14주는 `coming` 안내 페이지를 유지한다.
- 1주차 검증·Colab 실행 확인 후 2주차는 선행 본문을 먼저 작성했고, NEIS 전체 수집 완료 후 9절의 CSV 실습을 완성했다. 사용자 2주차 검증 완료와 3주차 작성 승인에 따라 아래 10절을 적용한다. 사용자 3주차 검증 후 11절에 따라 4주차를 완성했다. 후속 사용자 승인으로 12절의 5주차를 완성했다. 13절의 6주차 프로젝트를 완성했다. 14절에 따라 7주차를 작성했다. 현재 `week-01`~`week-07`은 `ready`, 나머지 8주는 `coming`이다.
- 주차 선택은 `ready`만 이동 가능하고, 이전·다음은 현재 주차도 `ready`인 경우에만 다른 `ready` 주차와 연결한다. `coming` 안내 페이지의 이전·다음은 비활성 상태이다.
- **GitHub Actions 선별 배포를 도입하지 않는다.** 빌드 없는 정적 파일 운영과 `.nojekyll`을 유지한다.

### 6-4. 확정된 사이트 구조와 데이터 배치

- B안: 학기 홈 `index.html` + 15개 주차 페이지 `week-01/index.html` ~ `week-15/index.html`.
- 폴더명, `levels[].slug`, `body[data-level]`은 `week-01` ~ `week-15`로 일치시킨다. 주차 번호로 URL을 식별한다.
- `data/site.js`에는 15주 순서·제목·차시·사용 데이터·교재 쪽수·학습목표·공개 상태를 담는다. 내용 변경은 이 문서를 먼저 갱신한 뒤 메타데이터와 HTML에 반영한다.
- 공통 `shared.js`, `base.css`, `tokens.css`, `DESIGN.md`와 강사 정보는 그대로 사용한다. 주차 이동은 `widgets.js`, 스타일은 `lecture.css`에서 확장한다.

## 8. 1주차 완성 범위와 이후 주차의 공통 형식 (3단계 사용자 승인)

### 8-1. 차시와 활동 순서

- 1차시: 과목 오리엔테이션 / 데이터 과학이란 무엇인가.
- 2차시: Orange3 설치와 첫 워크플로우.
- 3차시: Colab 접속과 같은 데이터를 Python으로 열기.
- 각 차시는 **질문 제기 → Orange3에서 결과 확인 → 개념에 이름 붙이기 → Python으로 재현 → 결과 비교** 순서를 지킨다.
- 설치 전인 1차시는 교사가 준비된 Orange3·Colab으로 표를 시연하고 학생이 관찰한다. 2차시에는 학생이 Orange3를 직접 조작하고 교사가 Python 그래프를 시연한다. 3차시에는 학생이 완성 코드를 직접 실행·변경한다. 교사는 수업 전에 아래 실습 환경과 코드 셀을 준비한다.
- 중심 질문은 일별 대여건수의 차이와 평균기온과의 관계다. 산점도에서 “기온이 높으면 대여가 많다”는 관찰을 출발점으로 삼되, 모든 날에 성립하는 규칙이나 인과관계로 단정하지 않는다. 9~11주차 회귀에서 이 관계를 예측에 사용하고 평가한다.

### 8-2. 실습과 데이터 설명

- Orange3 공식 설치 프로그램으로 설치한다. File에서 `bike-daily.csv`를 열고 **File의 Data 출력을 Data Table·Distributions·Scatter Plot에 각각 연결**한다. Data Table에서 353행과 8개 컬럼, Distributions에서 대여건수 분포, Scatter Plot에서 평균기온–대여건수 관계를 확인한다. 내장 데이터는 사용하지 않는다.
- 학생은 Python 문법을 이미 이수했다. 문법을 다시 가르치지 않고 pandas의 CSV 읽기·`head()`·`shape`·`describe()`와 Matplotlib 산점도 완성 코드를 제공한다. 축 변수와 공휴일여부 조건을 바꾸어 결과를 비교한다.
- Colab 접속·새 노트북·코드/텍스트 셀·실행·저장을 안내한다. CSV는 `pd.read_csv()`에 배포 URL `https://kimjinhyuk1984.github.io/ds-2026/data/weather-bike/bike-daily.csv`를 직접 넣어 `encoding="utf-8-sig"`로 읽는다. 파일 업로드는 접속 문제 시 보조 안내로만 둔다.
- Colab의 한글 표시는 **koreanize-matplotlib**로 통일한다. 1주차와 이후 2~15주차의 모든 Colab 실습은 아래 8-4의 표준 준비 셀을 사용한다. 사이트에는 외부 웹폰트나 런타임 의존성을 추가하지 않는다.

- 사용자가 `python scripts/collect-neis.py`로 전체 수집을 완료했다. 확정 파일은 `data/neis/schools.csv`(4행 × 8열), `data/neis/meals.csv`(1,504행 × 12열)이다. UTF-8 BOM, 학교코드 문자열 유지, 날짜 YYYY-MM-DD. 급식 표는 학교명·표준학교코드·급식일자·식사종류·요일을 포함하며 요일은 월·화·수·목·금·토·일이다. `요리명` 컬럼의 메뉴 원문(DDISH_NM)은 HTML 태그·알레르기 번호를 포함해 그대로 보존한다. HTML 태그 제거·알레르기 번호 분리·메뉴 분할은 학생의 5주차 전처리 실습이므로 수집 스크립트에서 처리하지 않는다. 원산지·영양 텍스트도 원문을 보존한다. 컬럼 사양·가공 단계·실행법은 data/README.md에 기록한다.
- 요청 크기는 최대 1000행, pIndex를 증가시키며 list_total_count와 실제 누계를 대조한다. 기본 요청 간격 1초와 제한된 재시도를 두고 인증 오류·조기 종료·중복 식별키를 확인한다. 출력에는 학교별 행 수·고유 급식일·식사별 일수·월별 건수·150일 미달 경고를 포함한다. 모든 대상 학교의 응답을 검증한 뒤 두 CSV를 저장한다.
- 재시도는 네트워크 타임아웃·HTTP 429·503만 허용한다. JSON이 아닌 응답은 상태코드와 무관하게 진단 후 즉시 중단한다. HTTP 500·그 밖의 연결 오류·업무 오류도 재시도하지 않는다. 재시도 불가 오류와 한도 초과는 --check의 다음 학교/날짜 요청까지 중단한다. 자료 없음과 학교/데이터 검증 실패는 요청 실패와 구별한다.

### 9-2. 인증키와 무인증 실습

- 학생은 키를 발급받지 않는다. 2차시 도입은 인증키 없이 학교기본정보를 요청하고 최대 5건만 받는 현상을 관찰한다. “왜 요청한 수만큼 오지 않을까?”를 질문한 뒤 API·인증키·요청 조건 개념을 붙인다. 표본이 5개보다 적은 검색도 있을 수 있으므로 서울 고등학교 전체 조건으로 제한을 확인한다.
- 무인증은 기본 sample key 동작이며 pIndex=1, pSize=5로 제한된다. 페이지 번호를 늘려 전체 수집을 시도하지 않는다. 5개를 서울의 전체 학교 수로 해석하지 않는다.
- 2차시 확장 활동은 학교 이름만 바꿔 친구가 다니는 학교나 이전 학교를 조회한다. 별도 요청 조건에서 지역·학교급 제한과 KEY를 제외하여 최대 5건으로 실제 조회가 된다는 것을 확인한다. 동명이교는 학교급·주소로 구별한다. 본 실습은 교사가 확정한 4개교 공통 데이터를 사용하고 자기 학교 분석은 학기말 프로젝트에서 다룰 수 있다고 안내한다. 급식 운영·자료량 차이가 있는 학생 선택 학교로 3주차 통합·13주차 연관분석의 공통 자료를 대체하지 않는다.
- 전체 수집과 기본 사전 확인은 교사 키로 하며 --check --no-key에서는 키를 사용하지 않는다. 키는 환경변수 **NEIS_API_KEY** 또는 실행 시 숨김 입력으로 받는다. 공백·개행·탭·따옴표·BOM을 제거하고 정제 후 길이만 출력한다. 보통 길이인 32자와 다르면 경고하며, 길이 일치가 유효성을 보장하지는 않는다. 실제 키를 명령줄 옵션·파일·로그에 기록하지 않는다. 실패 시 전체 요청 URL을 출력하되 키는 앞뒤 3자만 남겨 마스킹한다(6자 이하는 전부 마스킹). 응답 본문은 생략 없이 출력하면서 반사된 키도 마스킹하고, RESULT.CODE·RESULT.MESSAGE를 별도로 표시한다. HTTP 200의 업무 오류도 진단한다. 사용자 --check에서 HTTP 500이 보고되었으며 인증키 원인 여부는 비교 실행 후 판단한다.
- 공개 Colab 예제에는 **KEY = "여기에 인증키 입력"** 자리표시자만 둔다. 키는 수업 중 교사가 전달한다고 안내하며, 실제 키를 저장소·공개 노트북·출력에 남기지 않는다. 이 예제의 한 페이지 미리보기와 교사용 전체 수집 스크립트를 구분한다.

## 10. 3주차 — 빅데이터·데이터베이스와 데이터 통합 (2026-09-10 사용자 승인)

사용자가 2주차 검증을 완료하고 3주차 7~9차시 작성을 승인했다. 자료는 기존 schools.csv(4×8), meals.csv(1,504×12), bike-daily.csv(353×8)만 사용하며 배포 URL을 직접 읽는다. 교재는 관련 교재 p.23 (Ⅰ-2-1), p.29 (Ⅰ-2-2)만 참조한다. 본문은 새로 쓰고 교재 이미지·도표·문장·레이아웃을 사용하지 않는다.

### 10-1. 차시와 정확한 관찰

- 7차시: 따릉이 12개월 원본 **38,286,211행 → 수업용 일별 353행**을 소재로 처리 비용과 집계의 정보 손실을 설명한다. 원본 행 수는 대여건수 합계가 아니다. 최종 353행에는 기간 축소와 날짜별 서울 전체 합산, 기상 결합이 반영된다. 대여소·시간대 정보는 일별 합계만으로 복원할 수 없다. 빅데이터를 고정 행 수 기준으로 정의하지 않으며 데이터베이스·DBMS·데이터셋을 구분한다.
- 8차시: meals를 학교별 302/743/300/159행으로 나누어 Concatenate와 pd.concat으로 다시 1,504행×12열을 만든다. 명덕·세현 두 학교만 선택하면 902행이다. Orange는 컬럼 제거 옵션을 끄고 네 출력을 Additional Data에 연결해 원래 구조를 유지한다.
- **관찰의 정확성:** 동일한 12열·빈 값 0건인 원본을 학교별 분리 후 그대로 Concatenate하면 새 빈 값은 생기지 않는다. 명덕에만 조식이 있고 세현에는 석식 기록이 없다는 것은 학교·식사 종류의 조합에 해당하는 행의 부재다. 이를 셀의 결측과 혼동하지 않는다. 설명에 맞추려고 컬럼을 삭제하거나 가짜 결측을 만들지 않는다. 현재 구성은 원본 재결합의 빈 값 0건과 다음 차시 Merge의 새 빈 값을 구분한다.
- 9차시 A: 급식 표에 학교 표의 표준학교코드·설립구분·도로명주소를 left merge한다. 학교코드는 양쪽 문자열로 읽고 학교 표는 코드당 1행이다. Python 결과는 **1,504행×14열, 주소 빈 값 0건**이다. validate=many_to_one으로 기대한 관계를 확인한다.
- 9차시 B: 동양고·세현고 각각 **중식만** 골라 날짜당 1행인 두 표(180×2, 159×2)를 만든다. 컬럼은 급식일자와 학교별 이름으로 바꾼 급식인원이다. 결측치 제거가 아닌 비교 범위 선택이다. 날짜에 조·중·석 여러 행을 그대로 붙이는 다대다 결합과 구분한다.
- 동양을 왼쪽, 세현을 오른쪽으로 두고 급식일자 기준 결합: **inner 155행(빈 값 0), left 180행(세현 인원 빈 값 25), outer 184행(동양 인원 빈 값 4·세현 인원 빈 값 25)**이다. 왼쪽을 세현으로 바꾸면 left 159행이다. 실제 CSV의 날짜 집합에서 대조한 값이다.
- 실제 예: 세현의 마지막 기록은 2024-12-30. **2024-12-31은 동양 중식 380명만**, **2024-05-07은 세현 중식 510명만** 기록되어 outer 결과에서 상대 학교 인원이 빈 값이다. 모든 미매칭 날짜가 학기 말인 것은 아니다.
- 9차시 C: bike-daily에서 날짜·요일·공휴일여부·대여건수와 날짜·기온 3종·강수량으로 컬럼을 나누고 날짜 키로 재결합한다. 두 입력은 353×4와 353×5, 복원 결과는 **353×8**, 원래 컬럼 순서로 맞추면 값이 동일하다. 이는 완성 파일을 나누어 Merge 원리를 재현하는 활동이며 원본 재집계가 아니다. 강수량 빈 값은 전·후 200개로 유지된다.

### 10-2. 도구 대응과 학습 경계

- 매 차시는 질문 → Orange3 → 개념 → Python → 비교 순서다. 코드는 pre[data-code]이며 준비 셀에서 배포 URL을 읽고 후속 셀은 같은 노트북의 변수를 사용한다. 문법 설명 없이 학교 선택·결합 방식·입력 방향·관찰 날짜를 바꾸어 비교한다.
- Concatenate는 같은 의미의 컬럼을 맞추어 행을 모으는 작업, Merge는 키가 같은 행에 다른 정보를 붙이는 작업으로 설명한다. Merge에서는 방식이나 키 중복에 따라 행 수도 달라질 수 있음을 명시한다.
- Orange3 Merge Data의 Append columns from Extra Data=left, Find matching pairs of rows=inner, Concatenate tables=outer 대응을 안내한다. 마지막 선택 이름은 독립된 Concatenate 위젯과 구별한다. Orange의 inner/outer는 양쪽 키가 유일한 날짜 비교에서 다루고, 학교 정보의 다대일 결합은 left로 한다.
- 학교·날짜 키를 모두 실제 컬럼으로 지정하며 Row index로 연결하지 않는다. Select Rows에서 상수 컬럼 제거를 끄고, Select Columns로 분석 컬럼만 고르며, Edit Domain으로 학교별 인원 컬럼 이름만 바꾼다. 값·원본 CSV는 변경하지 않는다.
- 3주차는 새 빈 값의 위치·발생 원인만 관찰한다. fillna/dropna·Impute·메뉴 텍스트 분리·정규식은 제공하지 않는다. 강수량 빈 값의 의미와 처리 방법도 4주차에 남긴다.
- 본편은 표 비교 중심이다. 보충 그래프는 기본 발표에서 제외하고 S로 포함할 수 있다. koreanize-matplotlib 설치와 import를 한 셀에 두며 import 유지·재시작 불필요·새 런타임 재설치를 안내한다.

### 12-1. 차시와 수업 범위

- 데이터는 meals.csv(1,504행 × 12열)만 사용하며 배포 URL을 직접 읽는다. 교재는 관련 교재 p.67 (Ⅱ-1-2)만 참조한다. 13~15차시를 작성하고 1~5주 ready, 6~15주 coming으로 둔다.

- 14차시: 모든 괄호를 지우는 완성 코드의 실패를 찾는다. 시리얼(스페셜K외), 감자샐러드(깍둑)-조식, 갈치구이(국내산바질향 갈치토막), 호박죽(조식)의 설명 괄호를 보존한다. 갈치구이 예시는 사용자가 적은 ‘바닷질향’이 아닌 실제 CSV의 ‘바질향’으로 표기한다.
- 숫자·점 괄호만 고르는 개선안도 검토한다. 원문에 냉이된장국(24.03), 마늘보쌈(23.06), 등심돈까스(100)&소스^처럼 숫자 괄호가 메뉴 설명에 쓰인 항목 9개가 있다. 첫 숫자 괄호만 뽑거나 모든 숫자 괄호를 지우면 틀린다.
- 최종 수업 규칙은 원문 검토에 맞춰 끝의 숫자·점 괄호 1개를 후보로 찾고 모든 번호가 1~19인지 확인한 뒤 그 부분만 제거한다. 설명·앞쪽 숫자 괄호·별표·내부 공백·기타 문장부호는 보존하고 메뉴 양 끝 공백만 정리한다. 이 규칙도 미래 자료의 날짜·규격·비표준 표시까지 자동 판별하는 것은 아니다.
- 정규식은 처음부터 작성시키지 않는다. 실패 코드 → 실제 반례 찾기 → 조건을 강화한 완성 코드 → 보존된 정보 대조 순서로 사용한다. 강사 스크립트와 처리 결과를 도입부에서 링크하지 않는다.
- 15차시: 학교코드+급식일자+식사종류를 한 급식의 키로 사용한다. 메뉴 개수와 알레르기 번호가 표기된 메뉴 비율을 파생한다. 비율의 분모는 해당 급식의 전체 메뉴 항목 수이다. 표기가 없다는 사실을 실제 알레르기 유발 성분이 없다는 뜻으로 해석하지 않는다.

## 14. 7주차 — 기술통계와 추론통계 (사용자 승인)

사용자가 6주차 완료를 확인하고 7주차 19~21차시 작성·ready 전환을 지시했다. 각 차시는 질문 → Orange3 → 개념 → Python → 비교 순서로 구성한다. 교재 문장·이미지는 사용하지 않고 관련 교재 p.82 (Ⅱ-2-1)로만 연결한다.

### 14-1. 입력과 통계량 기준

- 기본 입력은 `data/weather-bike/bike-daily-clean.csv`다. 4주차에서 무강수 공백 200개를 0으로 반영한 결과를 이어받는다고 페이지 시작에 명시한다.
- 기간 2024-03-01~2025-02-16, 353행 × 8열, 빈 값 0개다. 다른 컬럼·대여건수·기간은 원본과 같다. CSV는 변경하지 않는다.
- 대여건수 평균 119,927.78186968839 → 표시 119,928건, 중앙값 126,749건, pandas 기본 표준편차 49,525.53445676132 → 표시 49,526건이다. 평균 대비 표준편차는 약 41.3%다.
- 기본 표준편차와 분산은 pandas의 n−1 기준을 표시한다. 전체 353개를 n으로 나누는 기준의 표준편차는 49,455.335223097085건으로 Orange3 Box Plot과 대조한다. 보충 셀에서 ddof=1/0을 나란히 출력하며 계산식 유도는 요구하지 않는다.
- Feature Statistics는 버전에 따라 Column Statistics로 표시된다. Dispersion은 분산 자체가 아니며, 수치 속성에서는 표준편차/평균이다. 평균·중앙값은 Box Plot으로 함께 확인한다.
- 353개 대여건수는 모두 달라 한 값의 최대 등장 횟수는 1이다. 두드러진 최빈값이 없다는 해석과, 요일 최빈값의 동률(금·토·일 각 51일)을 대조한다.
- 4주차 강수량 평균 8.12mm는 공백을 제외한 153개 기록, 3.52mm는 0 처리 후 353일의 평균이라는 계산 대상 차이를 되짚는다.

### 14-2. 19~21차시

- 19차시 기술통계: 평균·중앙값·최빈값·분산·표준편차의 의미를 데이터로 설명한다. Feature Statistics·Box Plot·겨울 Select Rows와 Python describe·mode·var·std·기간별 요약을 대조한다.
- 겨울(12~2월) 78일 평균 약 61,294건, 그 외 275일 약 136,558건으로 겨울의 낮은 값이 전체 평균을 끌어내리는 근거를 확인한다. 최저일은 2024-05-05이므로 낮은 값이 모두 겨울이거나 계절만이 원인이라고 단정하지 않는다.
- 20차시 분포·산포: Orange3 Box Plot·Distributions를 전체와 월별 Select Rows에 각각 연결한다. Python groupby().describe·공통 구간 히스토그램·월별 박스플롯으로 비교한다. 월은 연·월로 묶고, 2025년 2월은 16일임을 표시한다.
- 12개월 중 11개월의 기본 표준편차는 전체보다 작다. 2025년 1월은 약 20,964건이지만 2024년 5월은 약 54,671건으로 더 크다. 5월 대여건수 범위는 14,293~193,336건이다. “월별로 나누면 항상 줄어든다”로 서술하지 않는다.
- 21차시 모집단·표본: 이번 실습의 모집단을 이 파일의 353일로 정한다. 따릉이의 모든 과거·미래 날짜로 일반화하지 않는다. Orange3 Data Sampler는 원본 353행에서 Fixed sample size=30/100/200, 중복 추출·Replicable·Stratify를 해제하고 크기별로 다섯 번 확인한다.
- Python은 sample(n=…, replace=False)로 매번 새 표본을 확인한 뒤 크기별 100회 반복 평균을 표·박스플롯으로 비교한다. 반복마다 random_state를 바꾸며 같은 seed_start는 재현용, 다른 seed_start는 새 실험이다. 표본 크기와 반복 횟수를 구별한다.
- 반복 평균이 전체 평균 주변에 모이는 경향을 관찰하되 한 번의 큰 표본이 항상 더 가깝다고 보장하지 않는다. 표본으로 모집단을 추측하는 것을 추론통계로 정리한다. 반복 평균의 표준오차 계산·신뢰구간·가설검정은 넣지 않는다.
